# Raw input is sent only while the Session app is frontmost

Raw input goes to whatever app is frontmost, and a system alert can take that place at any time. The driver uses Accessibility actions first and sends Raw input only after it checks that the Session app is frontmost, immediately before the events. Before a click or send keys, the driver brings the Session app to the front, because a menu or a popover of an app that is behind opens and closes at once. If the Session app does not come to the front, the command fails with `invalid element state` and sends nothing. A failed test is better than keys typed into another app. Releasing held keys and buttons does not check the Frontmost app, because a release that fails would leave keys held.
